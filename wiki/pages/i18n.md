# Internationalization

The UI supports English (`en`) and Japanese (`ja`). The app does not use an i18n library. `client/src/composables/useI18n.js` does the work.

## How it works

- `currentLocale` is a module-level ref. Its start value comes from `localStorage` key `app-locale`, or `'en'` (`useI18n.js:11`).
- `t(key, params)` finds a dot-path key, for example `nav.dashboard`, in the active locale file. If the key is missing, it uses the English value.
- `setLocale(locale)` sets the ref and writes `localStorage`. All components that use `useI18n()` update at once, without a page reload.
- `translateProductName`, `translateCustomerName` and `translateWarehouse` use the name maps in `ja.js`.

## Currency

- `currentCurrency` is `JPY` when the locale is `ja`. Otherwise it is `USD`.
- `client/src/utils/currency.js` converts with a fixed rate, `USD_TO_JPY = 150`. It rounds JPY to whole numbers.
- The backend always returns USD values.

## Rule

When you add UI text, add the key to both `client/src/locales/en.js` and `ja.js`. Then call `t('your.key')` in the template.
